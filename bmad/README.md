# BMAD Workspace

This folder makes the project editable by large LLMs (Claude, Codex, GPT) in a modular way, without losing system context.

Full BMAD-METHOD assets are installed separately under `_bmad/`. This `bmad/` folder is the project-specific brownfield context layer and remains the source for domain routing and generated context packs in this repository.

## Goals

- Keep a stable architecture map for both services:
- `backtest-runner` (port `8002`)
- `market_regime_detection` (port `8001`)
- Partition work into domains with explicit boundaries.
- Generate compact context packs that can be loaded per task.
- Preserve a whole-system index for cross-domain changes.

## Source-Of-Truth Layers

1. Manual behavior/contracts:
- `docs/llm/functionality-map.md`
- `docs/llm/api-contracts.md`
- `docs/llm/invariants-and-validation.md`
2. Generated structural context:
- `bmad/context/generated/00-index.md`
- `bmad/context/generated/<domain>.md`
- `bmad/context/generated/00-machine-index.json`
- `bmad/context/generated/00-endpoint-map.md`

If manual docs and code diverge, code is authoritative and docs must be updated in the same change.

## Main Files

- `context/component-map.json`: canonical domain map.
- `context/generated/`: generated context packs (regenerated by script).
- `templates/`: story/task templates for structured LLM execution.
- `workflows/`: BMAD-style workflow adapted to this project.
- `backlog/`: epic tracks + machine-readable story board.

## Refresh Context Packs

Run:

```bash
python3 scripts/generate_context_pack.py
```

Then validate:

```bash
python3 scripts/validate_llm_context.py
```

## Claude Commands

Project commands are in `.claude/commands/`:

- `/bmad-system-map`
- `/bmad-plan`
- `/bmad-story`
- `/bmad-implement`
- `/bmad-review`

All command templates are schema-first and should consume generated machine index + domain packs.
